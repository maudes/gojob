# Changelog

All notable changes to Go Job are recorded here, newest first.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Changed
- **Backend files renamed for what they do; `pipeline.py` split in three.** `main.py` → `api.py`, `claude.py` → `model_client.py`, `prompts.py` → `context_blocks.py`, `skills.py` → `skill_loader.py`, `text.py` → `text_tools.py`, `requests.py` → `request_checks.py` (it no longer shares a name with the HTTP library), `demo.py` → `sample_data.py`, `meta.py` → `version_stamp.py`. `pipeline.py` became `audit.py` (the audit loop and quote proof), `scoring.py` (apply rule, tuning ceiling, score rounding) and `tasks.py` (what each button does); `now_iso` moved to `store.py`. Three skills were renamed: `audit` → `auditor`, `score-panel` → `panel-scorer`, `jd-verdict` → `jd-match`, so the per-skill fingerprints in older saved results and eval runs carry the old names and `--compare` shows them as changed. No behaviour change: all 169 tests pass. The start command is now `uvicorn gojob.api:app`.
- **Every score threshold is in `scoring.py`, and the browser follows it.** The profile health check's 80 / 70 was typed into `tasks.py` and `selftest.py`; it is now `HEALTH_NEED_AVERAGE` and `HEALTH_NEED_MIN`, next to the JD match gate's `JD_NEED_AVERAGE`, `JD_NEED_MIN` and the new `JD_TUNE_FROM` (the 60 between "tune" and "risky", which used to exist only in the browser). The two gates have separate constants so each can be tuned alone. `GET /api/state` now sends them as `config.thresholds`; the tier rule (`tier()` in `lib/text.ts`), the health gate sentence and the JD apply sentence take their numbers from there (the health sentence from the result's own `needAverage` / `needMin`, so it explains its own light), and the 繁中 strings carry `{average}`, `{min}`, `{tuneFrom}` placeholders. `tests/test_thresholds.py` checks that both gates use the constants, that the state sends them, that no gate number is typed into the browser code again, and that translated sentences keep their placeholders. Changing a threshold is now a one-file edit.
- **Resume from a Google Docs link works.** The resume link field used to be saved but never read. **Fetch from link** now downloads a Google Doc as Word (or a Drive file, Word or PDF) and treats it like an upload, so the revised resume is edited in place and keeps the doc's layout. The doc must be shared as "Anyone with the link"; a file that is not shared gets a clear message. The app still cannot write back to Google (that would need a Google sign-in), so changes come back as a downloaded .docx.
- **Layout lock for resume changes.** Tracked changes (profile health check, fine-tuning) can no longer land on the name, contact line, section titles, or employer, job title, date, place, school and degree lines; the app drops any such change after the model answers, and the change rules tell the model to keep every line about as long as the original and never add or remove lines. The sample changes shown without an API key follow the same rule (they used to append text to the first experience line). Checked on a real Google Docs resume: an in-place edit changed only text nodes, every other part of the file stayed byte for byte the same. A line break inside a Word paragraph no longer glues two words together in the extracted text.
- **Every prompt is now a skill file.** The prompts that lived in `prompts.py` are one file each under `backend/gojob/skills/` (16 files), with named `## part:` sections for pieces the code chooses between (language rule, each auditor's focus, each question category) and `{{include:name#part}}` for rules shared by several prompts (ground rules, resume change rules, visa signals, search honesty rules). `{{variable}}` marks values the code fills in. A skill is read from disk on every use, so an edit applies without a restart, and the prompt fingerprint follows file changes the same way. `prompts.py` keeps only the data blocks (profile, JD, scan settings) and the choice of which skill to use; `skills.py` is the loader. Every rendered prompt was checked against the old text and is identical, so behaviour does not change; the fingerprint changes once because the text moved. Tests check that every skill has a name and description, every include and variable resolves, every skill the code asks for exists, and that there are exactly five auditors. See `backend/gojob/skills/README.md`.
- **Prompts now stress the target JD's keywords.** Resume changes must replace generic wording with the exact term the JD uses for the same activity, only when the resume already shows that activity; an unsupported keyword still goes to "needs confirmation". Applies to the profile health check, fine-tuning (including headline tags) and the cover letter's ability paragraph. The prompt fingerprint changes with it. No eval measures this yet.
- **JD match gate is stricter.** Apply now needs an average of 80 and no reviewer below 70 (was 60), the same as the profile health check. Between 60 and 79 on average the tier is still "fine-tune and re-assess"; below 60 it is still "risky".

### Added
- **Command line and a subagent runner (no API key).** `npm run gojob -- analyze-jd` assesses one job description without the browser. With `--runner subagent`, Claude Code subagents answer the model calls instead of the Claude API: the code writes a request file for every call it needs and stops, subagents write the answers, and rerunning the same command reuses them until the assessment is done. The code, not the subagent, still decides what to ask and whether the result passes (five auditors above 95, every quote word for word). Results carry `meta.runner`. The `run-gojob` skill in `.claude/skills/` runs the loop. Requests and answers are kept in `data/manual/` (git-ignored). Command line only (not in the web app), and it assesses one JD. Adds 6 tests (175 in all).
- **Auditor eval (`npm run eval:audit`).** Tests the five fidelity auditors by planting mistakes on purpose: three correct answers (fine-tune, JD assessment, cover letter) and 19 faults written as small edits (altered quote, invented metric or skill, ownership inflation, placeholder labelled confirmed, wrong profile, wrong work authorisation, ...). It reports recall (faulty answers blocked), false alarms (correct answers blocked) and which faults slipped through, with limits of 90% and 34% as starting values. 17 tests check that every fault is real and that the scoring correctly fails a blind and a trigger-happy auditor. Not yet run against the real auditors.
- **Per-skill fingerprints.** Every stamp (`meta`) now has `skills`: one 6-character fingerprint per skill covering its file and the shared rules it includes. `--compare` in both eval commands prints which skills changed between two runs.
- **Copy a changed paragraph.** Every suggested resume change (profile health check and fine-tuning) has a **Copy** button that copies the whole paragraph as it would read after the change, without the bullet sign, to paste over the old one in your Google Doc. Changes you already accepted are included.
- **Documentation.** The README is now a short product overview: the five steps, how it decides, key decisions and two diagrams. Day-to-day notes, the code map, testing and releases moved to `docs/guide.md`. `docs/architecture.md` has three diagrams (system, JD analysis sequence, apply/tune/stop states) with their Mermaid sources in `docs/diagrams/`.
- **Tuning ceiling.** Fine-tuning may only reword what the resume already shows, so it cannot reach the threshold forever. A JD now stops at "Ceiling reached" when the latest fine-tune has no change the resume supports (every suggestion needs confirmation), or when a resume change raised the average by less than 1 point. The fine-tune button is then disabled and the backend refuses another fine-tune (409). Uploading a revised resume clears the ceiling until the next assessment.
- **`evals/`: an evaluation set for the AI.** Ten synthetic cases built as traps (missing metrics, keywords without evidence, participation inflated to leadership, work-authorisation wording, prompt injection in a job description, cover letter with no real motivation, messy PDF text, Chinese output), eleven code graders, an optional LLM judge for usefulness, a calibration tool that compares the judge with your own scores, and run-to-run comparison that flags regressions. `npm run eval -- --help`.
- Every run is saved with the app version, prompt fingerprint, models and git commit, so any two releases can be compared.
- 29 tests that check the graders themselves against hand-written good and bad answers.
- **Request checking.** Every JSON request is checked against a typed shape (`backend/gojob/requests.py`) before a route runs. A wrong type is answered with a 400 that names the field, and the shapes appear in the API docs at `/api/docs`. 16 tests.
- **Tests for the screen helpers.** `npm run test:web` runs 11 checks on tracked-change marks, JD tiers, the tracker row and applying accepted changes, using Node's built-in test runner (needs Node 22.18 or newer; running the app still works on Node 20). `npm test` now runs both the screen and backend tests.

### Known gaps
- Covers three tasks (JD analysis, resume tuning, cover letter). Not yet run against real model output.

## [1.0.0] - 2026-11-15

First tracked release. The backend moved from Node.js to Python; the screens and every feature are unchanged.

### Changed
- **Backend rewritten in Python (FastAPI).** All AI calls, the five-auditor review, quote checks, Word editing, job-page reading, the headhunter scan and the interview coach now live in `backend/`. The Next.js app only draws screens and forwards `/api/*` calls to it.
- The prompts were carried over word for word from the Node.js version, so the move itself does not change results. Two prompt changes made shortly before the move are part of this release: work-authorisation signals in the JD verdict, recruiter review and job scan, and the three-part cover letter (view and reason, ability, one sentence on work authorisation). They are now gathered in `backend/gojob/prompts.py` (the interview coach's prompts moved there from the coach module).
- Profile: "Countries where you can already work", so sponsorship is not treated as an issue for jobs there.
- Tracked changes are computed with the `diff` package instead of hand-written code. Marks are finer (a changed comma no longer marks the whole word), and a spacing-only edit no longer shows both spacings.
- `npm run dev` now starts both the web interface and the backend. Needs [uv](https://docs.astral.sh/uv/) installed.
- Screen code no longer depends on `docx`, `jszip`, `mammoth`, `unpdf` or the Anthropic SDK; those moved to Python equivalents (`python-docx`, `mammoth`, `pypdf`, `anthropic`).

### Added
- **Traceable results.** Every AI result is stamped with `meta`: app version, a `promptHash` fingerprint of all prompts, and the writer and auditor models. The footer shows the running version.
- **Data versioning.** `data/db.json` carries a `schemaVersion`. Older files are upgraded on first read and a copy is kept as `data/db.v0.bak.json`. A file written by a newer app is refused instead of being damaged, and a corrupt file is set aside instead of overwritten.
- **Test suite.** `npm test` runs 67 pytest checks covering the audit and repair loop, quote proof, approval gates, Word editing, link safety, data upgrades and every API route in sample mode. No test calls the Claude API.
- `CHANGELOG.md`, a git history and release tags.

### Fixed
- `.gitignore` now also excludes `data/files/`, which holds the uploaded resumes.
- A saved file whose JSON is damaged no longer gets silently replaced by an empty one on the next save.

### Known gaps
- Results created before v1.0.0 have no `meta` stamp.
- Frontend-only helpers (`diffOps`, `tier`, `trackerTSV` in `lib/text.ts`) no longer have the start-up self-test. (Tests added after this release, see Unreleased.)
- There is no evaluation set yet for measuring answer quality; the runtime audit checks faithfulness to the sources only.
